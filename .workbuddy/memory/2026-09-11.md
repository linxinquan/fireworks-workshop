## 烟火小作坊.html 代码审查（未改动文件）

单文件纯前端烟花小游戏（1979 行，vanilla JS + canvas，IIFE + try/catch 包裹），四步流程：选料→搅拌→装填→点燃。

审查结论（P1 真 bug，待确认后修）：
1. **高清屏坐标错位**：`fx.width = innerWidth*dpr`（@烟火小作坊.html:1089-1094）但全程用 CSS 像素坐标绘制，无 `ctx.setTransform`。
   DPR=2 时筒口/爆点在画布坐标只走到一半（视觉上跑到屏幕中间），粒子半径细一半；`p.y > fx.height+30`(1375) 底部剔除在 DPR>1 时基本失效。
   `sky` 星空画布是纯 device-px 体系且手乘 dpr 补偿（1030/1064），两套坐标体系混用，建议统一。
2. **星空只闪一次**：`init()` 的 rAF 循环 `if(!fxRunning) rAF(tick)`（@1963），startFx 置 true 后 tick 不再自注册，endFx 复位也没人重启 → 放完第一发烟花星空永久静止。resize 也救不回（resize handler 不调 tick）。
3. **mix<40 的"翻车剧情"不可达**：`updateMixUI` 在 m<40 时 `btnToPack.disabled=true`（@1716-1720），但 parseRecipe 里铜盐变绿白（@1421-1423）、colorName=green（@1538）、稀疏文案（@1552/1560）、enterLaunch 提示（@1770）全为它写了分支 → 设计意图与 UI 门槛打架。

P2 性能：粒子 trail 用 `history` 数组 + `shift()`（@1113-1115）+ 每粒子 `save/restore` + 轨迹描两遍（@1165-1183）；`drawSky` 每帧 `getComputedStyle(document.body)`（@1040，且 backgroundColor 实为 rgba(0,0,0,0)，`|| "#070b22"` 从未生效）；帧步长写死 1/60（@1341/1347/1373）导致 120Hz 屏幕 2 倍速；最坏粒子数约 900 无上限（`power` 公式 @1470-1471 + 搅拌/装填倍率叠加）。

P3 手感/清理：搅拌只取角度增量绝对值（@1681-1682），横穿碗心一次 atan2 翻转即加 ~180°，一抖手就能触发 >135 神秘效果，且最佳区间仅 40~115°（约 1/8~1/3 圈）太短；glossy 高光把主色稀释成 3/4 粉白（@1451-1458）；死代码 `rarity`/`TYPE_CLASS`/`params.styleWillow`/`recipeDialog`；无任何持久化，"炼金手札"只罗列原料、不记录放过的烟花；listbox 语义冲突、无键盘搅拌。

用户偏好：讨论优先，已确认结论后再动手改；倾向 P1/P2/P3 列表 + 行号引用。

## 第四轮：原料图标全部换成统一风格的 SVG（2379 行 → 2542 行）

用户诉求：用 SVG 生成原料图标替代 emoji，风格要统一。

### 做法

- 在文档里加了一个 `<svg width="0" height="0">` 定义块，用 **`<symbol id="ic-<原料id>">` 定义 16 个图标**，
  JS 侧只加一个 `ingIcon(id, cls)` 拼 `<use href="#ic-xxx">`。图标只写一遍，卡片/碗/清单/手札/结果卡五处复用。
- **统一约定**：viewBox 32×32；描边一律 `#241407` / 1.7 / round-join；填充一律竖向 `linearGradient`（高光→本色→暗部）；
  每个图标收在 4~28 的方框内；一道白色高光笔触。渐变用原料自己的 `color` 派生，图标颜色 = 烟花颜色，玩家能直接建立色彩预期。
- 16 个剪影：硝酸钾=结晶簇、硫磺=棱角矿块、木炭粉=炭块+暖色火星、锶盐=红宝石、钡盐=四叶草、铜盐=蓝色溶液滴、
  钠盐=柠檬(带叶)、铝粉=银白四角星芒、月光花瓣=月牙+花瓣、龙鳞粉=带同心纹的鳞片、凤羽灰=火苗、独角兽鬃毛=斜置螺旋角、
  星尘=光环+星、妖精之泪=彗星、雷鸟羽毛=闪电、影猫皮毛=猫头剪影（带竖瞳）。
- 顺手清掉已无引用的 `emoji` 数据字段（16 处）；`rcNote` 由 `textContent` 改 `innerHTML`（note 文案里现在嵌图标）；
  「基础药」提示、哑火/蓝变绿/钠盐盖色/神秘效果等文案里的原料 emoji 也一并换成图标。

### 关键经验

- **`.ico` 基类必须自带尺寸**：`<svg>` 没写 CSS 宽高会回落到 300×150。写成 `width:1.15em;height:1.15em`（随字号缩放），
  各场景再覆盖（卡片 27px / 碗 23px / 清单 19px / 手札 24px）。
- **视觉体量要量化**：第一版 `getBBox()` 量出最窄 11px、最宽 26px（差 2.4 倍），窄的（结晶柱、独角兽角）在大图标旁显得很轻。
  处理：窄的重画（结晶簇加左右侧晶、角改成斜置加粗），偏大的三个（铝粉/星尘/妖精之泪）用
  `<g transform="matrix(.88 0 0 .88 1.92 1.92)">` 包一层整体缩一档，最终收到 15~23px。
- **剪影撞形**：龙鳞和最开始的铜盐水滴都是"上尖下圆"，几乎分不出来 → 给鳞片加两条同心纹并改宽。
- **四瓣图形别用 4 个 rotate 副本拼**：中心会交叉出脏描边。改用一条路径
  `M16 11.6A4.4 4.4 0 1 1 20.4 16 A4.4 4.4 0 1 1 16 20.4 …Z`（四个 large-arc 弧）得到干净的四叶草。
- **SVG 圆弧半径不够会退化**：月牙的内弧半径 9 < 弦长一半 11，浏览器按规范把半径放大成 11 → 月牙退化成半圆。

## 第五轮：修结果卡「显示不全」（2543 行 → 2601 行）

用户反馈：结果卡底部/顶部被切（附 494×399 截图，视口约 502×430）。

### 根因（量出来的，不是看出来的）

用 `getBoundingClientRect` + `getComputedStyle` 逐项量，两个独立问题：

1. **`overflow-y:auto` 把 ribbon 剪掉一半**。`#step-launch .card` 同时是滚动容器，而 ribbon 是 `position:absolute;top:-14px`
   跨在上边框上 → 滚动容器按 **padding box** 裁切，14px 高的那半截被切掉。且 `overflow-y:auto` 会让未指定的
   `overflow-x` 计算成 `auto`，两个方向都裁。四个视口全部复现（`ribbon.rect.top` 比卡片顶高 9~11px）。
2. **矮视口内容溢出**。844×390 时卡片可用高 346px，内容实需 374px → 必须滚动才能看到「原料」行，初始状态底部被裁 15px。
   512×430 / 320×400 亦然。原因是结果卡的排版完全没有针对矮视口压缩。

### 改法

- **滚动下移到内层**：HTML 里把 ribbon 之外的内容包进 `.card-body`；`.card` 改
  `display:flex;flex-direction:column;overflow:visible`（限高仍在），`.card-body` 负责 `min-height:0;overflow-y:auto;overflow-x:hidden;overscroll-behavior:contain`。
  ribbon 回到外层就不会被裁。`showResult()` 里顺带 `cardBody.scrollTop = 0` 复位。
- **补两档矮视口压缩媒体查询**（放在所有媒体查询之后，避免优先级反被覆盖）：
  `@media (max-height:660px)` 收紧 padding/名字字号/stat padding/note 行高/按钮/原料行；
  `@media (max-height:470px)` 再压一档。改完 844×390 内容降到 265px（可用 346），五个视口全部 `scrollHeight === clientHeight`。
- **底部原料行重排**：原来是一整串字符串，窄屏会把「压实 适中」从中间断成两行（用户截图里的「压实 适 / 中」）。
  改成 flex-wrap 的**原子片段**：每个「图标+原料名」是一个 `.fx-ing-seg{white-space:nowrap}`，
  分隔符 `·` 写进片段**内部**（否则 `<span class="sep">·</span>` 自成一项会掉在行尾变成孤立符号），
  「搅拌 N°」「压实 X」两组用 `.tail{border-left:1px solid}` 做组间分隔 —— 边框跟着内容换行，不会掉队。

### 坑 / 经验（已补进技能）

- **`overflow:auto` 容器会按 padding box 裁掉子元素的负向偏移**；症状是"卡片顶部徽章缺一半""滚到底仍看不全"，
  极易误判成截图时序问题。判据是把装饰元素与卡片两者的 rect + `getComputedStyle(...).overflow` 一起打出来比。
- flex-wrap 行里的分隔符不能自己当一项（见上）。
- **别轻易给截图空白帧下结论**：中途有一次竖屏截图拍出来是空帧，但探查显示卡片 `opacity=1 / visible / z=6 / rect 正常`——
  是截图时序抖动。为此加了双阶段标记（probe-a/probe-b）在不同时刻各拍一张，并给驱动里的 `testReport` 节点加 `display:none`
  避免这个诊断节点本身影响布局。

### 铝粉 SVG 的两个瑕疵（**已报告用户，未改源码** —— 用户惯例是"原样贴"）

2. **颗粒纹理读不出来 + 意外"表情"**：4 个 `fill="#fff"` 颗粒圆是**白堆上的白点**，肉眼不可见；
